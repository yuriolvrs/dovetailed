  - **Model switch, same session, per explicit user request** ("are there options for a free model that is stronger/has more usage limits? this always happens" -- reacting to a `JsonParseError` failure): `worker/wrangler.toml`'s `LLM_MODEL` changed from `llama-3.1-8b-instant` to `openai/gpt-oss-120b`, confirmed against Groq's live docs (free tier: 1K requests/day, 200K tokens/day, vs. the 8B model's 14.4K/day, 500K/day -- still generous for one user) and sanity-checked directly against the real API before/after. Config-only change (`llm.ts` is already provider/model-agnostic per CLAUDE.md). **Found live, fixed immediately:** GPT-OSS is a reasoning model (emits a separate `reasoning` field consumed by the existing `content`-only extraction, harmless) but a direct API test of the real cover-letter prompt showed it sometimes ignores the "one sourceMap entry per paragraph" instruction and merges all paragraphs into a single entry instead -- structurally valid JSON that `isCoverLetterGeneration` was not yet checking for, which would silently break `CoverLetterEditor`'s per-paragraph badge matching (every paragraph would wrongly show as unevidenced, including ones the model actually did cite evidence for). New unit test covers the rejection; reconfirmed clean live afterward (154 tests total, 1 new).
  - **Second real-model finding, same session, from the user hitting "LLM proxy response had no content" live:** direct API testing traced this to `openai/gpt-oss-120b`'s chain-of-thought reasoning being billed as completion tokens against the same `max_tokens` budget as the actual JSON answer -- confirmed live, the reasoning alone consumed 1075-1200 of the cover letter call's 1200-token budget, hitting `finish_reason: "length"` and cutting the response off mid-JSON (or, on a harder prompt, before any content token at all). Testing every other `generateStructured` call site at its existing budget under the new model found the same truncation actually already happening in **matching** (`matchRequirement.ts` via `runMatching.ts`, 300 tokens) and **bullet-reword suggestions** (`suggestBulletRewrite.ts`, 300 tokens) -- both silently broken by the model switch, not just cover letters -- while posting analysis (1500 tokens) survived but with thin margin. Reconfirmed each fixed with a direct API call (all now `finish_reason: "stop"`) and live through the real app (re-ran matching, regenerated a cover letter with the writing-style toggle on -- the exact original repro -- both completed with no error).
