- 2026-08-28 - Fixed garbled punctuation in imported/exported data. Reported as an import/export bug ("McDonald[a-circumflex]s" in a job posting, "Sambayan [a-circumflex] Lasalyano" in a resume entry); the exported JSON was checked byte by byte first and the export/import path itself is faithful -- `JSON.stringify` + `Blob` + `file.text()` round-trip C1 code points unchanged (verified in Node), so the damage was already in IndexedDB before any export. Root cause: the mojibake `llm.ts` already knew about (the model mis-emits multi-byte UTF-8 punctuation as separate Latin-1 code points) arrives with its invisible C1 code points (U+0080-U+009F) missing, leaving a bare U+00E2 that the existing `fixMojibake` could not decode and so left alone. The user's backup held 165 of them. New `src/lib/repairText.ts` (`repairText`) replaces `fixMojibake`: it keeps the byte-level decode for intact runs, rebuilds a character exactly when one byte survived ("[a-circumflex][cent]" -> a bullet), and for a fully stripped character reads the likeliest punctuation mark from its neighbours -- a right single quote before a possessive or contraction, a hyphen between two words, an em dash standing alone. The guessing half only runs when the text carries a mojibake marker, so genuine accented words ("chateau", "cafe") are untouched; a real accented letter that went through the same damage still decodes exactly, because its two code points both survive. Wired into `llm.ts` (all three previous `fixMojibake` call sites) and into both ends of backup: new `serializeBackup()` in `backup.ts` repairs the JSON text on the way out (used by `BackupControls.tsx`'s Export button), and `parseBackup()` repairs it on the way in, so re-importing an existing backup heals data already stored. Repair runs over the whole JSON document rather than field by field, so one garbled character anywhere in the file vouches for the rest -- a single damaged field on its own has no evidence and is left as found (tested). New `repairText.test.ts` (11 tests) plus 3 backup round-trip tests. Checked against the user's real 2026-08-27 backup: all 165 bare characters repaired, output still parses as JSON. `npm run test` (373) green and `tsc --noEmit` clean.
