# UX Polish Plan

Follow-up work items from a resume-viability review, scoped to UI/UX polish only (no new product features). Each item should be verified live in the running app before being checked off, per CLAUDE.md.

## Checklist

- [x] **Hover-based sourceMap detail** — done 2026-08-19, resume side removed 2026-08-19 per direct feedback. New `AtomHoverDetail` primitive (`src/components/ui/primitives.tsx`) wraps a badge in a pure-CSS hover tooltip listing the exact profile atom(s) (source label + verbatim quoted text) a bullet/paragraph is grounded in. Originally wired into both resume bullets and cover-letter paragraphs, but the resume side was pulled back out after live testing showed it was repetitive: a resume bullet is copied verbatim from the profile, so hovering its badge just re-showed the exact text already sitting right there in the field below it. Kept on cover-letter paragraphs (`CoverLetterEditor.tsx`, "Grounded in your profile" badge) where it's actually load-bearing — a paragraph is AI-synthesized prose that can combine multiple profile facts into one sentence, so the hover is the only way to see which atom(s) it came from; previously an evidenced paragraph showed no indicator at all, only unevidenced ones got a warning badge.
- [x] **Loading/skeleton states for all async actions** — audited 2026-08-19, no code changes needed. Checked every LLM/OCR call site in the app (posting analysis + reanalyze, AI-categorize skills, matching + re-match, resume/cover-letter generation + regenerate, LaTeX template conversion, resume import, the new job-document import, bullet-rewrite suggestions, writing-sample/template file attachments) and every page-level initial load — each already has a proper pending state (disabled button + spinner + "…ing" label, a multi-part progress readout for LaTeX conversion and matching, a cancelable progress bar for matching, or a `Skeleton`/`PageSkeleton`), all via the shared primitives. This item was written during the earlier resume-viability review before this codebase's incremental polish work (Phase 7, plus this session's own features) had actually closed the gap; nothing found needed fixing.
- [x] **Consistent empty states across all sections** — done 2026-08-19. New `EmptyState` primitive (`src/components/ui/primitives.tsx`, with a `size="sm"` default for in-list/in-card empty states and `size="lg"` for a whole empty page) replaces five places that were hand-duplicating the same dashed-box class string (`EditableList.tsx`, `AnalysisEditor.tsx`'s empty requirements list, `ResumeExperienceSection.tsx`, `ResumeEducationSection.tsx`) or drifting slightly from it (`MatchingReviewPage.tsx`'s per-requirement gap explanation, `JobsPage.tsx`'s zero-postings state) — all now render through one component instead of six copies of the same styling. Left two spots alone on purpose: `TagInput`'s empty placeholder and the Matching page's "No evidence attached yet." line are both already nested inside their own bordered container, where a second dashed box would add clutter rather than consistency; and the richer icon+heading+CTA cards (Analyze this posting, Write a tailored cover letter) are a different kind of moment (a feature's first-run call to action) than a bare empty list, so weren't forced into the same shape. Verified live via Playwright: Jobs' zero-postings state and Profile's empty Experience tab both render through the shared component with the intended visual weight for their context.
- [x] **Dark mode** — done 2026-08-19. Tailwind class-based dark mode (`darkMode: 'class'`), a `ThemeToggle` button in the app header, and `src/lib/theme.ts` (localStorage-persisted, falls back to OS preference) plus a tiny inline script in `index.html` that applies the theme before first paint so there's no light-then-dark flash on load. `dark:` variants added across every shared primitive (`Card`, `Btn`, `Badge`, form fields, `Modal`, `EmptyState`, `AtomHoverDetail`, etc.) and every page/component with its own one-off colors — roughly 30 files. Deliberate exception: `ResumePrintView.tsx`/`CoverLetterPrintView.tsx` (the actual resume/cover-letter document, both the live preview pane and the print/PDF output) stay permanently light, since they represent a real document being exported, not app UI — flipping the preview dark and then back to light on export would be inconsistent, and print output should always read like paper. Verified live via Playwright: toggled dark mode, confirmed it persists across a reload, and screenshotted Jobs/Profile/Job Detail/Matching/Generate — the editor panels follow the theme while the resume preview stays white throughout. `npm run build` and `npm run test` (293) both green.
- [x] **Version diff/comparison view** — built 2026-08-19, removed the same day per direct feedback ("not helpful"). Had added a line-level diff (a new `diffLines.ts`/`diffableLines.ts`/`VersionDiff.tsx`) behind a "Compare" button in both History popovers, but it didn't earn its keep in practice, so all of it was deleted rather than left unused. Alongside the removal, the cover letter's History UI (previously its own full-width `Card` under the header) was also converted into a popover matching the resume tab's, since that's what it was compared against — same trigger/backdrop/panel pattern, single "Restore" button per version, no diff.
- [x] **Autosave confirmation indicator** — done 2026-08-19. New `useAutosaveIndicator()` hook (a `pulse()` call flashes a `saved` flag on for ~1.8s, restarting on each call so a burst of edits reads as one steady flash) and a `SavedIndicator` primitive (a fading "✓ Saved" label, the mirror image of the existing `UnsavedIndicator`). Wired into every page whose fields autosave immediately on change: `ProfilePage.tsx` (next to the completeness meter), `JobDetailPage.tsx` (next to "Posting Text," swapping with the existing `UnsavedIndicator` depending on whether that field specifically is mid-edit), `GeneratePage.tsx`'s resume editor, and `MatchingReviewPage.tsx` (evidence/additional-info edits). Verified live via Playwright: confirmed the indicator's opacity goes from 0 → ~0.9 immediately after an edit, then back to 0 after ~2s, with a screenshot showing the flash next to Profile's completeness meter.
- [x] **Toast/inline confirmations for actions** — audited 2026-08-19; most actions already had feedback (`BackupControls`, `ImportResumeSection`, the `justSaved`/`rawSaved` flags in `TexTemplateSection`, the `Toast`/`useToast().showUndo` bar used by posting delete and clear-matches). Found and fixed four silent ones: `TexTemplateSection`'s "Remove template" (new `removedMessage` state, fades on next edit like its sibling save confirmations), and three version-history/export actions that closed their popover with no confirmation — `GeneratePage.tsx` and `CoverLetterSection.tsx`'s "Restore" (now also closes the History popover and flashes a "Restored" `SavedIndicator`) and `GeneratePage.tsx`'s "Export .tex" (flashes an "Exported" `SavedIndicator`). `SavedIndicator` (`primitives.tsx`) gained an optional `label` prop so it can say "Exported"/"Restored" instead of always "Saved", rather than duplicating its markup. Verified live: removing a saved template shows "✓ Template removed."
- [x] **Multi-step generation progress** — audited 2026-08-19, no code changes needed. Matching (`MatchingReviewPage.tsx`) already shows a per-requirement `ProgressBar` during rematch, since it's genuinely a loop of separate calls. Resume generation (`selectResumeContent.ts`, synchronous) and cover-letter generation (`generateCoverLetterContent.ts`, one LLM call) aren't actually multi-step internally, so a step breakdown would be decorative rather than informative — left as the existing single "Writing…" label.
- [x] **Manual reordering (drag-and-drop)** — done 2026-08-19. `EditableList`'s existing `reorderable` prop (drag handle + drag-and-drop, already used by Experience/Project entries and their bullets) was only missing from a few lists that had add/remove but no reorder: Education entries, Skill categories, and the Links sub-lists on Contact and each Project (`EducationForm.tsx`, `SkillsForm.tsx`, `ContactForm.tsx`, `ProjectsForm.tsx`) — each just needed the prop passed, no new plumbing. Verified live: drag handles appear on all four.
- [x] **Accessibility pass** — done 2026-08-19. Audited focus rings (already solid — `Btn` and `fieldInputClass` both have `focus:ring-2` variants) and icon-only buttons (already have `aria-label`, e.g. `RemoveItemButton`, the tag-remove ×, modal close ×). The real gap: `FieldInput`/`FieldTextarea`/`FieldSelect` (`primitives.tsx`) rendered a `<label>` next to its input with no programmatic association — fixed with `useId()` generating a shared id, wired to the input via `id`/`htmlFor` on all three. Verified live: 8 `label[for]` associations found on the Education tab alone.
- [x] **Responsive/mobile layout check** — done 2026-08-19. Found and fixed unconditional `grid-cols-2` (no mobile fallback) in `JobsPage.tsx`'s add-posting modal, `ContactForm.tsx`, `EducationForm.tsx`, and their resume-editor counterparts `ResumeContactSection.tsx`/`ResumeEducationSection.tsx`/`ResumeExperienceSection.tsx` — changed to `grid-cols-1 sm:grid-cols-2`. Caught a second, easy-to-miss half of the same bug live via Playwright: a `col-span-2` div inside one of these grids doesn't get clamped to 1 column by the browser when the grid itself drops to `grid-cols-1` — CSS Grid instead adds an *implicit* extra column to satisfy the span, which re-created the 2-column cramped/overlapping layout the `grid-cols-1` fix was supposed to remove. Fixed by changing those to `col-span-1 sm:col-span-2` as well (`ContactForm.tsx`, `EducationForm.tsx`, `ResumeContactSection.tsx`, `ResumeEducationSection.tsx`). Verified live via Playwright at a 375px viewport: Education tab now renders as a clean single column with full-width fields, confirmed via computed `grid-template-columns` before and after.

## Re-audit of completed items — 2026-08-19

A second pass over the items already checked off above, looking for gaps the first pass missed. Five found and fixed; the rest held up.

- **Dark mode — native controls.** `color-scheme` was never declared, so the browser drew *native* UI in light mode regardless of any `dark:` class: the `<input type="date">` calendar popup and its washed-out `mm/dd/yyyy` placeholder (the visible symptom on the Job Detail page), plus select dropdowns and spinners. Fixed in `index.css` with `color-scheme: light` on `html` and `dark` on `html.dark`.
- **Dark mode — scrollbars.** `index.css`'s `scrollbar-color`/`::-webkit-scrollbar-thumb` were hardcoded to slate-300/400, correct on a white panel but a bright bar against dark cards. Added `.dark` overrides stepping them to slate-700/600.
- **Accessibility — Escape to close.** All five overlays (the shared `Modal`, plus the History and Export popovers in `GeneratePage`, `CoverLetterSection`, `InterviewPrepSection`) had outside-click-to-close but no Escape handler. Added `src/lib/useEscapeKey.ts` (callback held in a ref so an inline arrow doesn't re-subscribe the listener each render) and wired it into all five. `Modal` also gained `role="dialog"` / `aria-modal="true"`, which it was missing entirely.
- **Toast — not announced.** The undo toast rendered as a plain `<div>`, so a screen reader never heard "Posting deleted." Added `role="status"` / `aria-live="polite"`.
- **Responsive — two missed grids.** The mobile pass fixed unconditional `grid-cols-2` in six files but missed `ExperienceForm.tsx` (Company + Job Title) and `DateRangeFields.tsx`'s outer Start/End wrapper — the latter the worse of the two, since each half splits again into month/year, putting four dropdowns across a 375px screen. Both now `grid-cols-1 sm:grid-cols-2`; the inner month/year pairs stay 2-up at all widths on purpose.

Held up under re-audit, no changes: loading/skeleton states, empty states, autosave indicator, multi-step progress, drag-and-drop reordering, focus rings and `label`/`htmlFor` associations.

## Notes
- Items above are UX/polish only — no changes to data model, LLM prompts, or generation logic are expected as part of this plan.
- Loading-state and empty-state items should reuse the existing shared primitives in `src/components/ui/primitives.tsx` rather than introducing new one-off patterns.

### Explicitly rejected (do not build)
- Multiple saved profiles/personas — the single-profile model already supports this; the user enters everything and generation selects what's relevant per posting.
- Local-model (Ollama) mode.
- Fit-score visualization.
- Multiple resume/cover-letter variants per job — adds a choice the user shouldn't have to make.
